# Global Learn — Документация системы

## Пользователи

Единственный тип аккаунта — **EMPLOYEE** (сотрудник компании). Имеет роль, принадлежит к департаменту и отделу. Все авторизованные пользователи — сотрудники.

> Раньше существовал тип `CLIENT` (внешний пользователь). Раздел и тип удалены.

### Область видимости статистики

Контрольная панель показывает данные в зависимости от роли:

| Роль | Что видит |
|------|-----------|
| `admin` | Всех сотрудников |
| `department_head` | Только свой департамент |
| `division_head` | Только свой отдел |
| `senior_manager` | Только тех, кому он назначал курсы |
| `manager` | Только себя |

---

### Одобрение заявок на курсы

Когда сотрудник самостоятельно подаёт заявку на курс (а не назначается), её должен одобрить **руководитель** (любая роль с доступом к контрольной панели: `admin`, `department_head`, `division_head`, `senior_manager`).

```
Компания

    └── Отдел (Division)
        └── Сотрудник (Employee)
               → роль, должность, дата принятия на работу
```

## Функциональные области

### Курсы

Курс — основная единица обучения. Содержит модули → шаги → элементы (уроки или тесты).

**Структура курса:**
```
Курс
└── Модули []
    └── Шаги []
        └── Элементы []
            ├── Урок (Markdown-текст)
            └── Тест (вопросы с вариантами, минимальный % прохождения)
```

**Статусы курса:**

| Статус | Описание |
|--------|----------|
| `draft` | Черновик, недоступен пользователям |
| `pending` | На проверке у администратора |
| `published` | Опубликован, доступен |
| `archived` | Архивирован |

**Целевая аудитория курса:**

| Тип | Кто видит |
|-----|-----------|
| `employee` | Только сотрудники определённого таргета |
| `all` | Все сотрудники |

Дополнительно курс может быть нацелен на конкретный **департамент** или **отдел**.

**Кто может создавать курсы:** `admin`, `department_head`, `division_head`.

---

### Запись на курс

Существует два пути зачисления сотрудника на курс:

#### 1. Прямое назначение (управленцем)
```
Назначение → статус: in_progress → курс сразу доступен
```
Доступно: `admin`, `department_head`, `division_head`, `senior_manager`.

#### 2. Самостоятельная заявка (требует одобрения)
```
not_enrolled → pending_approval → in_progress → completed
                               ↘ rejected
```
Любой пользователь может подать заявку. Руководитель одобряет или отклоняет.

**Прогресс** рассчитывается как: `(пройдено элементов / всего элементов) × 100%`.

При достижении 100% автоматически выдаётся **сертификат**.

---

### Онбординг

Система онбординга помогает руководителям провести нового сотрудника через серию задач при вступлении в должность.

**Типы шагов онбординга:**

| Тип | Описание |
|-----|----------|
| `task` | Произвольная задача |
| `document` | Ознакомление с документом |
| `meeting` | Встреча/собрание |
| `video` | Просмотр видео |
| `course` | Прохождение курса (ссылка на курс) |

Каждый шаг может быть `required: true` (обязательным) и иметь срок (`dueDate`).

**Шаблоны vs Назначения:**
- **Шаблон** — многоразовый план онбординга (можно нацелить на роль/отдел/департамент)
- **Назначение** — конкретный шаблон, применённый к конкретному сотруднику

**Внутри назначения:**
- Сотрудник отмечает выполненные шаги
- Может оставлять **фидбек** к каждому шагу
- Есть **чат** между сотрудником и руководителем — единственное место в системе, где есть чат

**Видимость:**
- Сотрудник видит только **свои** назначения
- Руководитель (с доступом к `canControl`) видит назначения, которые **он создал**

---

### Контроль и статистика

Доступно: `admin`, `department_head`, `division_head`, `senior_manager`.

**Режимы просмотра:**
1. **По курсу** — агрегация записей по каждому курсу
2. **По человеку** — агрегация записей по каждому сотруднику

**Метрики по курсу:**
- Завершили / В процессе / Не начали
- Всего записано
- Процент завершения

**Метрики по человеку:**
- Завершено курсов / В процессе / Не начато
- Всего курсов
- Средний прогресс

**Фильтры:** поиск по имени, фильтр по департаменту, фильтр по статусу записи.

---

### Сертификаты

**Сертификат курса** — выдаётся автоматически при 100% прохождении курса.
- Отображается в профиле
- Можно открыть/распечатать
- Золотая цветовая схема
- Подпись: «СЕРТИФИКАТ О ПРОХОЖДЕНИИ КУРСА»

> Дипломы за треки (learning paths) удалены вместе с самим разделом треков.

---

### Профиль

Доступен всем авторизованным пользователям.

**Содержит:**
- Имя, email, тип аккаунта
- Роль, департамент, отдел, должность, дата рождения, дата принятия на работу
- Выбор аватара
- Статистика: пройдено курсов / в процессе / всего записей / сертификатов
- Список всех сертификатов за курсы

| Главная | Всегда |

| Мой онбординг | Всегда (EMPLOYEE) |

**Бейджи на иконках:**
- Курсы — количество курсов на проверке (только admin)
- Мой онбординг — количество активных назначений
- Онбординг (управление) — количество активных управляемых назначений

## Ключевые бизнес-правила

1. **Заявка = одобрение** — самостоятельная запись на курс не даёт мгновенного доступа: нужно одобрение руководителя.
2. **Прямое назначение** — обходит заявку: курс сразу становится `in_progress`.
3. **Видимость курсов** — определяется типом (`employee`/`all`) и таргетом (департамент/отдел).
4. **Скоупинг по роли** — `admin` видит всех, `dept_head` — свой департамент, `div_head` — свой отдел, `senior_manager` — назначенных лично, `manager` — только себя.
5. **Сертификат** — выдаётся автоматически при достижении 100% прогресса.

## Стек и архитектура

**Стек:** React 19, TypeScript, Vite, React Router v7, TanStack Query, Zod, axios, Tailwind v4 + CSS Modules, lucide-react, motion.

**Архитектура:** Feature-Sliced Design (FSD).

```
src/
├── app/        # провайдеры, роутер, layouts, глобальные стили
├── pages/      # страницы-маршруты
├── widgets/    # составные UI-блоки (sidebar, course-list)
├── features/   # пользовательские сценарии (assign-course, certificate)
├── entities/   # доменные модели (user, course, onboarding, company, invite)
└── shared/     # инфраструктура (api, libs, query keys, zod schemas)
```

**Алиасы:** `@app`, `@pages`, `@widgets`, `@features`, `@entities`, `@shared`.

### Работа с API

- `shared/api/axios.ts` — единый axios-инстанс с auto-refresh при 401 (cookie-based auth).
- `shared/api/schemas.ts` — zod-схемы для валидации ответов на границе.
- `shared/lib/query/queryKeys.ts` — централизованный реестр query keys.
- Server-state живёт в TanStack Query cache, не в React Context. Контексты только для auth user и UI-state.

### Текущее состояние

Все entity-API сейчас mock-овые (in-memory). План перевода на реальный бэкенд — см. `docs/api-migration-plan.md`.
