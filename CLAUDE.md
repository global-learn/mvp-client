# Global Learn — Документация системы

**Global Learn** — корпоративная система обучения (LMS), предназначенная для обучения сотрудников компании и её клиентов. Система поддерживает создание курсов, назначение обучения, последовательные треки (learning paths), онбординг новых сотрудников и управление клиентами.

## Типы пользователей

Система различает два принципиально разных типа аккаунтов:

| Тип | Описание |
|-----|----------|
| **EMPLOYEE** | Сотрудник компании. Имеет роль, принадлежит к департаменту и отделу. Доступны треки, онбординг, чат. |
| **CLIENT** | Внешний пользователь — клиент партнёрской компании. Видит только курсы типа `client` или `all`. |

Клиенты не имеют ролей и организационной иерархии — только аккаунт и принадлежность к компании-клиенту.

## Роли сотрудников

У каждого сотрудника есть одна из пяти ролей:

| Роль | Отображение |
|------|-------------|
| `admin` | Администратор |
| `department_head` | Руководитель департамента |
| `division_head` | Руководитель отдела |
| `senior_manager` | Старший менеджер |
| `manager` | Менеджер |

### Область видимости статистики

Контрольная панель показывает данные в зависимости от роли:

| Роль | Что видит |
|------|-----------|
| `admin` | Все сотрудники и клиенты |
| `department_head` | Только свой департамент |
| `division_head` | Только свой отдел |
| `senior_manager` | Только те, кому он назначал курсы |
| `manager` / `CLIENT` | Только себя |

---

### Одобрение заявок на курсы

Когда сотрудник самостоятельно подаёт заявку на курс (а не назначается), её должен одобрить **руководитель** (любая роль с доступом к контрольной панели: `admin`, `department_head`, `division_head`, `senior_manager`).

## Организационная структура

```
Компания
└── Департамент (Department)
    └── Отдел (Division)
        └── Сотрудник (Employee)
               → роль, должность, дата принятия на работу
```

Особые отделы:
- **Сервисный отдел** (`isService: true`) — сотрудники этого отдела могут управлять клиентами и назначать им курсы. Обычно это отдел продаж или клиентского сопровождения.

## Функциональные области

### Курсы

Курс — основная единица обучения. Содержит модули → шаги → элементы (уроки или тесты).

**Структура курса:**
```
Курс
└── Модули []
    └── Шаги []
        └── Элементы []
            ├── Урок (Markdown-текст)
            └── Тест (вопросы с вариантами, минимальный % прохождения)
```

**Статусы курса:**

| Статус | Описание |
|--------|----------|
| `draft` | Черновик, недоступен пользователям |
| `pending` | На проверке у администратора |
| `published` | Опубликован, доступен |
| `archived` | Архивирован |

**Целевая аудитория курса:**

| Тип | Кто видит |
|-----|-----------|
| `employee` | Только сотрудники |
| `client` | Только клиенты |
| `all` | Все |

Дополнительно курс может быть нацелен на конкретный **департамент** или **отдел**.

**Кто может создавать курсы:** `admin`, `department_head`, `division_head`.

---

### Запись на курс

Существует два пути зачисления сотрудника/клиента на курс:

#### 1. Прямое назначение (управленцем)
```
Назначение → статус: in_progress → курс сразу доступен
```
Доступно: `admin`, `department_head`, `division_head`, `senior_manager`.

#### 2. Самостоятельная заявка (требует одобрения)
```
not_enrolled → pending_approval → in_progress → completed
                               ↘ rejected
```
Любой пользователь может подать заявку. Руководитель одобряет или отклоняет.

**Прогресс** рассчитывается как: `(пройдено элементов / всего элементов) × 100%`.

При достижении 100% автоматически выдаётся **сертификат**.

### Треки обучения

Трек (Learning Path) — упорядоченная последовательность курсов. Каждый следующий курс открывается только после завершения предыдущего.

**Статусы шага:**

| Статус | Значение |
|--------|----------|
| `locked` | Предыдущий шаг не завершён |
| `not_enrolled` | Доступен, заявка не подана |
| `pending_approval` | Заявка на рассмотрении |
| `rejected` | Заявка отклонена |
| `in_progress` | Курс проходится |
| `completed` | Курс завершён ✅ |

**Целевая аудитория трека:**

| Тип | Кто видит |
|-----|-----------|
| `all` | Все сотрудники |
| `department` | Сотрудники конкретного департамента |
| `division` | Сотрудники конкретного отдела |
| `managers` | Менеджеры конкретного отдела |

**После завершения трека** (все шаги = `completed`):
1. Автоматически выдаётся **диплом о завершении трека**
2. Один раз показывается **праздничная модалка** с конфетти
3. В баннере трека появляется кнопка «Открыть диплом»
4. Диплом отображается в профиле в секции «Дипломы о треках»

**Кто может создавать треки:** `admin`, `department_head`, `division_head`, `senior_manager`.

---

### Онбординг

Система онбординга помогает руководителям провести нового сотрудника через серию задач при вступлении в должность.

**Типы шагов онбординга:**

| Тип | Описание |
|-----|----------|
| `task` | Произвольная задача |
| `document` | Ознакомление с документом |
| `meeting` | Встреча/собрание |
| `video` | Просмотр видео |
| `course` | Прохождение курса (ссылка на курс) |

Каждый шаг может быть `required: true` (обязательным) и иметь срок (`dueDate`).

**Шаблоны vs Назначения:**
- **Шаблон** — многоразовый план онбординга (можно нацелить на роль/отдел/департамент)
- **Назначение** — конкретный шаблон, применённый к конкретному сотруднику

**Внутри назначения:**
- Сотрудник отмечает выполненные шаги
- Может оставлять **фидбек** к каждому шагу
- Есть **чат** между сотрудником и руководителем прямо в онбординге

**Видимость:**
- Сотрудник видит только **свои** назначения
- Руководитель (с доступом к `canControl`) видит назначения, которые **он создал**

---

### Клиенты

Раздел доступен только `admin` и сотрудникам **сервисного отдела**.

**Структура:**
```
Компания-клиент (ClientCompany)
└── Клиенты (CLIENT-пользователи)
```

**Возможности:**
- Создавать компании-клиенты
- Приглашать клиентов по email (инвайт действует 7 дней)
- Видеть список клиентов по компаниям
- Назначать клиентам курсы (тип `client` или `all`)
- Общаться с клиентами через чат

---

### Контроль и статистика

Доступно: `admin`, `department_head`, `division_head`, `senior_manager`.

**Режимы просмотра:**
1. **По курсу** — агрегация записей по каждому курсу
2. **По человеку** — агрегация записей по каждому пользователю

**Вкладки:**
- Сотрудники
- Клиенты (только `admin`)

**Метрики по курсу:**
- Завершили / В процессе / Не начали
- Всего записано
- Процент завершения

**Метрики по человеку:**
- Завершено курсов / В процессе / Не начато
- Всего курсов
- Средний прогресс

**Фильтры:** поиск по имени, фильтр по департаменту/компании, фильтр по статусу записи.

---

### Сертификаты и дипломы

**Сертификат курса** — выдаётся автоматически при 100% прохождении курса.
- Отображается в профиле
- Можно открыть/распечатать
- Золотая цветовая схема
- Подпись: «СЕРТИФИКАТ О ПРОХОЖДЕНИИ КУРСА»

**Диплом трека** — выдаётся при завершении всех курсов трека.
- Отображается в профиле в отдельной секции «Дипломы о треках»
- Фиолетово-синяя цветовая схема (визуально отличается от сертификата)
- Подпись: «ДИПЛОМ О ЗАВЕРШЕНИИ ТРЕКА»
- Указывает количество пройденных курсов

---

### Профиль

Доступен всем авторизованным пользователям.

**Содержит:**
- Имя, email, тип аккаунта
- Для сотрудников: роль, департамент, отдел, должность, дата рождения, дата принятия на работу
- Выбор аватара
- Статистика: пройдено курсов / в процессе / всего записей / сертификатов / дипломов
- Список всех сертификатов за курсы
- Список всех дипломов за треки (если есть)

- Курсы — количество курсов на проверке (только admin)
- Мой онбординг — количество активных назначений

## Ключевые бизнес-правила

1. **Последовательность в треке** — шаг N недоступен, пока шаг N-1 не завершён. Первый шаг всегда открыт.
2. **Заявка = одобрение** — самостоятельная запись на курс не даёт мгновенного доступа: нужно одобрение руководителя.
3. **Прямое назначение** — обходит заявку: курс сразу становится `in_progress`.
4. **Видимость курсов** — курс типа `employee` не видят клиенты, курс типа `client` — не видят сотрудники.
5. **Сервисный отдел** — только `isService: true` + admin могут управлять клиентами и назначать им курсы.
6. **Прогресс трека** — вычисляется динамически из статусов записей, в БД не хранится.
7. **Инвайты истекают** через 7 дней после создания.
8. **Диплом трека** — выдаётся идемпотентно: повторные посещения страницы не создают дубликатов.
9. **Праздничная модалка** — показывается один раз на пользователя на трек (через `localStorage`).
